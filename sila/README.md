# صلة | wifi-chat

> **ملاحظة:** هذا المستودع **مُوحّد الآن ضمن مشروع رسن** كوحدة `sila/` —
> github.com/tibatechapp-ship-it/Rasan — حيث تُخدم الواجهة على `/sila` من
> الخادم مباشرة، مع نقل حقيقي بين الأجهزة عبر مساحة `/sila` في Socket.IO،
> وساحات حيّة بعدّادات حقيقية. هذا المستودع يبقى مرجعاً تاريخياً فقط.

تطبيق تواصل اجتماعي عربي يعمل بواجهة هجينة: يزامن عبر الإنترنت عند توفره، ويتيح التواصل المحلي عبر Mesh بين التبويبات والأجهزة القريبة.

## هيكلية المشروع

تم إعادة هيكلة الكود باستخدام نمط MVVM (Model-View-ViewModel):

```
src/
├── main.js                 # نقطة الدخول الرئيسية
├── style.css              # التنسيقات
├── components/            # مكونات الواجهة
│   ├── uiRenderer.js     # توليد HTML
│   └── eventHandlers.js  # معالجات الأحداث
├── services/             # طبقة الخدمات
│   └── meshService.js    # خدمة التواصل الشبكي
├── state/                # إدارة الحالة
│   └── appState.js       # الحالة المركزية
└── utils/                # دوال مساعدة
    └── helpers.js        # دوال عامة
```

## ما يعمل الآن

- واجهة RTL متجاوبة لسطح المكتب والهاتف.
- مساحات محادثة قابلة للتبديل (ومن داخل رسن: انضمام حقيقي عبر `sila:join` + عدّادات حقيقية من `sila:peers`).
- إرسال رسائل فوري داخل نفس المتصفح عبر `BroadcastChannel`، ومن داخل رسن: نقل حقيقي بين أجهزة مختلفة عبر مساحة `/sila` في Socket.IO.
- مؤشر حالة الإنترنت، وعدّاد العقد القريبة، وتمييز مسار الرسالة: `Mesh` أو `Net` أو `P2P`.
- **نقل مباشر جهاز-إلى-جهاز (WebRTC DataChannel — تقنية Meshenger):** الإشارة عبر مساحة `/sila` والبيانات تسير مباشرة بين الجهازين على الشبكة المحلية بلا خادم وسيط — نقل مزدوج مع إزالة تكرار (القنوات المباشرة + الخادم معاً)، وشارة عدّاد «قنوات مباشرة (P2P)» في لوحة الحالة.
- إعدادات آمنة عبر `.env.example` مع استبعاد `.env` من Git.
- **كود مُعاد هيكلة:** فصل الاهتمامات، وحدات ES6، سهولة الصيانة والتوسع.

> ~~طبقة Mesh الحالية هي أساس الواجهة والنقل المحلي. ربط أجهزة مختلفة فعليًا يحتاج signaling عبر WebRTC أو خدمة محلية على الشبكة، وسيضاف في مرحلة الخادم التالية.~~
> **تم**: النقل الحقيقي بين الأجهزة يعمل الآن عبر مساحة `/sila` في Socket.IO داخل رسن (server/sila-mesh.js) — بلا DB ولا مصادقة ولا تخزين. WebRTC الجهاز-لجهاز مباشر في خارطة P1 لرسن.

## التشغيل

```powershell
npm install
npm run dev
```

افتح الرابط الذي يعرضه Vite، ثم افتح تبويبًا ثانيًا لاختبار الرسائل المحلية بين العقد.

لإنشاء نسخة الإنتاج:

```powershell
npm run build
npm run preview
```

## تطبيق Flutter

توجد نسخة الهاتف داخل `flutter_app/`، وتستخدم Flutter لتشغيل الواجهة على Android وiOS. Flutter غير مثبت في بيئة التطوير الحالية، لذلك لم يتم بناء APK هنا.

بعد تثبيت Flutter:

```powershell
cd flutter_app
flutter pub get
flutter run
```

لإنشاء نسخة Android:

```powershell
flutter build apk --release
```

نسخة Flutter الحالية تحتوي واجهة المحادثة ومبدّل `Mesh`/`Internet`. ربط Mesh بين أجهزة حقيقية يحتاج طبقة WebRTC أو signaling محلية في المرحلة التالية.

## التكامل مع رسن (أصبحت هذه الوحدة جزءاً من مشروع رسن)

أُدمج هذا المستودع في [رسن](https://github.com/tibatechapp-ship-it/Rasan) تحت `sila/` عبر `git subtree`.
ما الجديد بعد الدمج:

- **العميل يُخدم مباشرة** من خادم رسن على المسار `/sila` — لا حاجة لـ Vite (يبقى اختيارياً للتطوير فقط).
- **نقل حقيقي بين الأجهزة**: بالإضافة إلى BroadcastChannel (نفس المتصفح)، يتصل العميل بمساحة
  `/sila` في Socket.IO عبر `src/services/netBridge.js` — كل جهاز يفتح `/sila` من الخادم يصبح
  عقدة في نفس الساحة. على الشبكة المحلية يعمل بلا إنترنت خارجي، وعبر الإنترنت عند توفره.
- **عزل كامل عن نواة رسن**: المساحة بلا قاعدة بيانات ولا مصادقة ولا تخزين — نموذج أولي
  غير مشفر طرف-لطرف، والحدود: 4000 بايت للنص و10 رسائل/10 ثوان لكل عقدة.
- اختبارات الحواجز: `tests/sila.test.js` في مستودع رسن.
- خطة تطوير الميزات القادمة (PTT، طوابير أوفلاين، WebRTC المباشر): `docs/FEATURE_RESEARCH.md`.
