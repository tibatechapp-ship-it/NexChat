# بحث الميزات: مشهد التطبيقات المشابهة لرسن وصلة

> جمع وتحليل ميزات المشاريع المشابهة — مفتوحة ومغلقة المصدر — لتحديث مشروع رسن.
> تاريخ البحث: 2026-10-30. أُدمجت «صلة» (wifi-chat سابقاً) ضمن هذا المستودع تحت `sila/`.

## 1) الملخص التنفيذي

رسن اليوم يجمع ما تميّزت به أفضل التطبيقات المشابهة: تشفير طرف-لطرف حقيقي (ECDH P-256 + AES-GCM + TOFU) بلا أرقام هاتف، مجموعات وقنوات بث واسعة، رسائل متلاشية وStories، مذكرات صوتية مشفّرة، إنذار طوارئ بث جماعي، طابور أوفلاين بمؤشرات تسليم، وPWA خفيفة بـ12 لغة. أُدمجت «صلة» (wifi-chat سابقاً) ضمن هذا المستودع تحت `sila/` مع نقل Mesh حقيقي بين الأجهزة (`sila/` + مساحة `/sila` على الخادم). الفجوة الكبرى المتبقية هي **الصوت الفوري PTT** (المرحلة P1 عبر WebRTC) و**النقل المحلي متعدد القفزات** — انظر الخارطة أدناه.

## 2) المشاريع المدروسة

| المشروع | المصدر | النقل | التشفير | الأبرز |
|---|---|---|---|---|
| **BitChat** | مفتوح (Public Domain) | BLE Mesh + إنترنت (نقل مزدوج) | E2EE بلا حسابات | تعدد القفزات، قنوات بأسلوب IRC، بروتوكول موحّد iOS/Android |
| **Briar** | مفتوح (GPL-3.0) | Bluetooth + WiFi + Tor | E2EE بين المتحدثين | Mailbox للتخزين-والتمرير، منتديات، مسح ذعر (Panic wipe) — دخل وضع الصيانة يوليو 2026 |
| **Bridgefy** | مغلق (SDK تجاري) | BLE (~100م) تعدد قفزات عبر هواتف الغير | استخدم E2EE — نقدها تدقيق 2020 | 12.5 مليون مستخدم، يعمل في الكوارث والاحتجاجات |
| **Meshtastic** | مفتوح (GPL-3.0) | LoRa (كيلومترات) | AES-256 للقنوات | عقد خارج الهاتف، شمسية، مشاركة GPS |
| **Meshenger** | مفتوح (GPL-3.0) | P2P عبر WiFi مباشرة | E2EE (مفاتيح QR) | مكالمات صوت/مرئي بلا خادم إطلاقاً |
| **Serval Mesh** | مفتوح (GPL-3.0) | WiFi P2P | E2EE | اتصالات كوارث، هوية بلا بنية تحتية |
| **Session** | مفتوح (GPL-3.0) | شبكة Onion لامركزية | E2EE + مسارات بصلة | حسابات مجهولة تماماً، مجتمعات 100+، رسائل متلاشية |
| **Offline Protocol** | مفتوح جزئياً (AGPL + تجاري) | BLE Mesh + Nostr | MLS (RFC 9420) + Ed25519 | SDK جاهز: 8 قفزات، مستندات مكرَّرة (خريطة/نص/عدّاد) |
| **Zello** | مغلق | إنترنت/WiFi | خاص | PTT حقيقي، قنوات 6000 مستخدم، إنذار طوارئ، استماع خلفي |
| **FireChat** (متوقف) | مغلق | Mesh: BT + WiFi P2P (~70م) | لا E2EE كامل | نجاح ميداني هونغ-كونغ 2014 ثم موت — درس إدارة المحتوى |
| **WhatsApp** | مغلق | إنترنت (طوابير أوفلاين) | E2EE (Signal) | وضع Walkie-Talkie 2025، تشغيل خارج المحادثة، تفريغ نصي للصوت |

الخلاصة: نفّذنا مرحلة P0 كاملة: **(أ) المذكرات الصوتية**، **(ب) الطوابير أوفلاين بمؤشرات التسليم**، **(ج) إنذار الطوارئ**، **(د) ساحات صلة الحية**. المتبقي الكبير: WebRTC (مكالمات + LAN-direct) في P1، والنقل متعدد القفزات في P2.

## 4) خارطة الطريق المرحلية

### المرحلة P0 — مكاسب سريعة — ✅ منفّذة (2026-10-30)
1. ~~**مذكرات صوتية**~~: ✅ زر 🎤 + MediaRecorder → تشفير E2EE → رفع → رسالة `kind:"voice"` بمشغّل صوتي ومدة. (PTT بضغطة-زر الحقيقي انتقل إلى P1 مع WebRTC)
2. ~~**طابور أوفلاين صريح**~~: ✅ طابور `localStorage` + عرض متفائل بعلامة ⏳ + `message:ack` من الخادم → ✓، واستبدال echo عبر `clientId` بلا تكرار
3. ~~**إنذار الطوارئ**~~: ✅ `POST /api/conversations/:id/emergency` (كوت-داون 60ث) → Socket لكل من في الغرفة + FCM بالقالب الثابت لغير المتصلين + تفضيل `emergencies` (عمود مُرحّل + مبدّل جوال)
4. ~~**إكمال ساحات صلة**~~: ✅ تبديل الساحات عبر `sila:join` + عدّادات حقيقية من `sila:peers` + نبض حضور كل 30ث

### المرحلة P1 — بنية (شهور)
5. **WebRTC مباشر للأجهزة في نفس الشبكة**: تمرير SDP/ICE عبر مساحة `/sila` لاتصال جهاز-لجهاز بلا خادم وسيط للبيانات (تقنية Meshenger) — يعمل في WiFi المنزل/المخيم.
6. **مكالمات صوت/مرئي داخل رسن**: WebRTC مع الإشارة عبر Socket.IO الحالي.
7. **دراسة MLS (RFC 9420)** لتشفير المجموعات الكبيرة بدل مفتاح الإصدار الواحد — نمط Offline Protocol.
8. **اكتشاف الحضور بالـ BLE على الأندرويد**: حزمة Flutter BLE للإعلانات القريبة تُغذّي عدّاد العقد في صلة (أساس BitChat).

### المرحلة P2 — استراتيجي
9. **Mesh متعدد القفزات على BLE**: تمرير رسائل عبر هواتف قريبة (بروتوكول BitChat/Bridgefy) مع ack/retry/dedup كما في Offline Protocol.
10. **بوابة LoRa (Meshtastic)**: جسر MQTT لعقد خارجية للمناطق كلياً بلا تغطية.
11. **مسح ذعر + وضع اضطرار** (Briar): PIN منفصل يفتح نسخة فارغة، ومسح فوري بالمفتاح.
12. **مستندات مكرَّرة** للحالة المشتركة (قوائم/عدادات) عبر العقد كما في Offline Protocol.

## 5) الدروس الأمنية المستفادة من المشهد

- **تدقيق Bridgefy 2020**: استخدام التشفير الخاطئ جعل الرسائل قابلة للفك من مشغّل الشبكة — رسن يطبّق E2EE حقيقي منذ اليوم الأول ويجب ألا تدخل أي طبقة نقل جديدة بلا تدقيق مسار التشفير.
- **موت FireChat**: نجاح تقني بلا إدارة محتوى ولا نموذج تشغيل لا يدوم — قنوات رسن تحتاج أدوات إشراف قبل التوسع.
- **وضع صيانة Briar**: الاعتماد على مشروع بشركة ناقصة خطر — رسن يبني طبقاته الخاصة بدل الارتهان لـSDK مغلق.
- **صلة (sila) غير مشفرة طرف-لطرف عمداً كنموذج أولي**: معزولة عن نواة رسن (بلا DB ولا مصادقة) ويجب الإعلان عن ذلك في واجهتها قبل أي استخدام حقيقي — راجع `server/sila-mesh.js` و`tests/sila.test.js`.
